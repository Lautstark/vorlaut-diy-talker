Pushing content down the cable

The browser half of docs/cable.md, on its own — the last of the standalone benches, now that ttscheck and tilecheck have gone with the Python they measured against. It speaks the same tools/cable.js the static site will use, to a real device over WebSerial or to the mock in tools/cable_mock.js when there is no device to hand.

The wire

Connecting once is the whole setup. requestPort() needs a click to open the picker, so it can only be reached from a button — but getPorts() hands back a port that was granted earlier with no click at all, which is why this page tries that by itself on load. Plug the cable in, pick the device once, and every visit after that connects on its own. That is also why there is no five-digit code any more: the plug is the proof that somebody is standing in front of the device.
WebSerial needs a secure context, so this page has to be served — over http://localhost or over https, not opened as a file.

What is on it

Checksumming all of them is not what a push does — a name is a hash of what went into the file, so a name being there is answer enough, and only layout.bin has to be asked about. This is the deep check: it reads every file back off the device and compares it with what was sent.

Something to push

Use the directory picker. It reads firmware/vorlaut/data/ straight off the disk with nothing in between, which is what you want for a first run on real hardware: a failure is then the wire or the firmware rather than one of several new things at once. An invented payload needs nothing set up at all and proves the protocol on its own. Ticking the box changes part of an invented payload, which is how the case that matters gets tested: almost nothing should transfer the second time.
The editor sends by itself now. There used to be a button here that asked it for its build, and it could not work: this bench is served on its own port, and a different origin is a different IndexedDB — there is nothing of the editor's for it to read. What replaced it is the editor's own Send to the device, which builds and pushes down this same tools/cable.js in one press. This page is what is left over for the cases that button cannot reach: an invented payload, a folder off the disk, and the mock.
